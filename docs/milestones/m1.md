# M1: the 2D continuous experience

Finished 2026-10-18. Plan: DESIGN.md §10. How to use it: [docs/guide.md](../guide.md).

## What was built

**Problems** (crates/core/src/problems.rs): ten 2D problems (several also N-D) with analytic gradients, a
default finite-difference Hessian, and editable coefficients (`specs`, `build`). The shader expression is
generated from the current coefficients; known minima are analytic for textbook values and found numerically
(`find_minima`, Newton from a 14×14 grid) when coefficients move them.

**Optimizers** (crates/core/src/optimizers/): GD with three step rules, momentum, Nesterov, AdaGrad, RMSProp,
Adam, AdamW, Newton with modification, L-BFGS, Nelder–Mead; shared line searches (backtracking; strong Wolfe
with cubic zoom). Each carries pseudocode from its cited source, the deviations of the code from it, and `tr!`
calls recording every executed line with its values. Generic tests check every optimizer: convergence on the
bowl, cited source, valid deviations, traced lines exist and are step lines, tracing doesn't change results,
determinism.

**Session** (crates/core/src/session.rs): up to 8 runs in lockstep from a shared start; parameter-change log
with exact replay (`seek`) and branching; stopping points; per-run `Monitor` health with diagnosis
(crates/core/src/monitor.rs, ADR 0006); `inspect` (trace of the last step by replay); `fit_view`; `pick`
(ray-marching the drawn surface).

**Engine** (crates/wasm): `Engine` wraps `Session`; `build_frame` lays out trails (long segments subdivided to
drape over the surface), simplex shapes, minima, markers, health and descent directions for the frame
transport.

**Renderer** (web/src/render): back-ends now draw a list of items (trail strips and point sprites) from three
buffers; per-run colours with halos; health-aware markers; trails clipped at the view box; contour view
(orthographic, pan/zoom); picking (ray or surface coordinates).

**UI** (web/src/ui): state in `state.svelte.ts`; components for the top bar, problem panel with coefficients,
runs panel with generated inspector (sliders, exact values, choices), algorithm panel with live values and
line stops, bottom bar with timeline, stops panel, notices, canvas convergence charts, info panel; share links in
the URL hash.

## Tests

44 Rust (core + wasm), 4 GPU (all shader expressions incl. custom coefficients vs the Rust reference, pipelines,
renders, basins kernel), 12 browser (boot and fallbacks, stepping and scrubbing, runs, pseudocode, coefficients,
step-size divergence and its fix, unbounded saddle and zoom out, stopping points and line stepping, free camera,
contour + share link). `just test`, `just test-gpu`, `just e2e`.

## Deferred

Learning-rate schedules (noted as a deviation in AdamW) · dragging the start with a live re-run · problem
thumbnails · generated TS types (protocol.ts is hand-kept) · ambient occlusion · a gradient field beyond the
single arrow.

## Known limitations

- WebGPU is unverified in a real browser (headless Chromium here can't present it); WebGL2 is tested.
- Threaded WASM scales 4.1× on 12 cores vs 8.2× natively (allocation in parallel loops; fix planned in M2).
- Line stepping walks through a step that has already happened: the marker shows the iterate after it.
- Divergence thresholds are heuristics, tuned to avoid false alarms; may need revisiting for N-D problems.
- The contour view has no axes or tick labels yet; phones get a cramped layout (not a target).

## After M1 (2026-10-19)

- **Security audit, then public** (docs/security.md): history scanned for secrets (none), dependencies audited
  (clean), untrusted share-link parameters clamped, a strict Content-Security-Policy and related headers on the
  production server (the browser tests run under them), CI with a read-only token and pinned actions. The
  e2e runner now starts the preview server itself (Playwright's own launcher stalled here) on 127.0.0.1.
- **Several starting points and random restarts** (owner's request): runs hold one walker per start (the
  clicked point plus random points shared by every run, up to 64); walkers restart from a random point when
  they converge and/or fail; each run tracks its best point. Deterministic, so the timeline replays it
  exactly. This is the first half of M2's many-start mode (the GPU basins map is the other).
